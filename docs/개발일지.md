## 결정과 이유

- **과제 B에는 AI 기능을 넣지 않았습니다.** 수강생이 「외부 AI 서비스에 넣으려면 보안 사항을 삭제하여도 어려울 것」이라고 답했기 때문입니다. 지연·임박 판정은 브라우저 안의 규칙 계산으로 합니다.
- **과제 A는 반자동입니다.** 공개 자료 정보(브랜드·자료 종류·제목·출처 주소)만 담은 프롬프트를 만들어 복사하고, NotebookLM·Dify 답변을 붙여 넣으면 「신규 기능 / Sales Point / 스펙 비교 / 한줄 요약」으로 나눕니다. 출처가 없는 줄과 등록하지 않은 자료 번호(S9 등)를 가리키는 줄은 경고합니다. 기획 원칙 「모든 요약에 원문 출처 표시」를 화면에서 확인할 수 있게 한 것입니다.
- **개발 단계는 전 기종 공통 목록 하나로 둡니다**(수강생 답변). 설정에서 이름·순서를 고치며, 이름이 같은 단계는 연결된 일정·이슈를 그대로 유지합니다. 일정·이슈·자료에서 쓰는 단계는 실수로 빼지 못하게 막았습니다.
- **기종마다 「이슈 관리함」 버튼과 저장소 링크**를 두었습니다(수강생 답변). 현황표 기종 칸, 기종 목록, 기종 상세 어디서든 그 기종의 이슈 관리함으로 갑니다. 저장소 링크가 웹 주소면 새 창으로 열고, 사내 공유 폴더 경로(`\\서버\폴더`)면 복사합니다. 브라우저는 보안상 파일 탐색기 경로를 직접 열지 못하기 때문입니다.
- **Outlook MSG는 이슈 근거로 붙입니다**(수강생 답변). 1단계에서는 파일명과 저장 위치만 기록하고 파일 자체는 저장하지 않습니다. 자료 목록도 같습니다. 개발 중 기종 자료를 브라우저 저장소에 복사해 두지 않기 위함이고, 브라우저 저장소 용량(보통 5MB)도 곧 넘기 때문입니다. 파일 보관 위치는 사내 보안 기준 확인 뒤 2단계에서 정합니다.
- **일정 Excel은 한 행 = 한 기종·한 단계 형식을 가정**했습니다(기획서 8장의 표준 양식). 실제 열 이름이 달라도 동의어로 자동 짝을 찾고(모델명→기종, Phase→개발 단계, 완료예정일→종료일 등), 사용자가 고친 짝은 저장해 다음 가져오기 때 다시 씁니다. 맨 위 제목 행은 건너뛰고 머리행을 찾으며, 직접 행 번호를 바꿀 수도 있습니다.
- **다시 가져오기는 덮어쓰기가 아니라 병합**입니다. 같은 기종·단계가 있으면 날짜·담당자만 새 값으로 바꾸고, 담당자가 표시한 완료와 메모는 남깁니다. 「한 명이 Excel 을 갱신하고, 상세 일정은 기종 담당자가 수정」한다는 기획 원칙을 함께 지키려는 것입니다.
- **일정 상태 판정 순서**: 완료 표시 → 종료일 지남(지연) → 종료일까지 임박 기준일 이내(임박) → 시작일 지남(진행중) → 예정. 임박 기준일은 설정값(처음 7일)이고 고정 값을 코드에 두지 않았습니다.
- **스크립트를 ES module 이 아닌 일반 스크립트로** 불러옵니다. `index.html` 을 파일로 열면(file://) 브라우저가 module 스크립트를 막아 화면이 비기 때문입니다. 사내 망에서는 파일로 여는 방법이 가장 현실적입니다.
- 예시 데이터의 기종·단계·브랜드·스펙은 모두 「예시」를 붙인 가상 값입니다. 실제 경쟁사 이름이나 스펙을 넣지 않았습니다.

## 가정

- 이슈 상태는 열림 / 조치중 / 종결 세 가지로 두었습니다. 이슈 번호는 `ISS-0001` 형식으로 자동 채번합니다. 사내 이슈 번호 체계가 있으면 바꿔야 합니다.
- 예시 공통 단계(구상 · 설계 · 시작품 제작 · 시험·검증 · 양산 이관)는 시연용 가정입니다. 실제 단계 명칭은 받지 못했습니다.
- 「임박」은 종료일 기준입니다. 시작일 임박(곧 시작해야 하는 단계)도 따로 봐야 하는지는 확인이 필요합니다.
- Bench Marking 비교 스펙 항목은 사용자가 적는 칸으로 두었고, 예시에만 「운전중량·버킷 용량·엔진 출력」을 넣었습니다(기획서 10장 10번 확인 필요).
- 과제 A의 공개 자료를 외부 AI(NotebookLM 등)에 넣는 것은 가능하다고 보았습니다. 사내 규정상 허용되는지는 기획서 10장 4번에 남겨 두었습니다.
